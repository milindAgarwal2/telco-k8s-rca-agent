# Session notes — 2026-10-27

## 1. Built the Runbook RAG admin GUI (shipped as 0.4.0)

Two separate, additive runbook sources feed `suggested_next_steps` — neither
replaces the other:

- **New**: `LocalRunbookRetriever` (`rag/runbook_retriever.py`) — retrieves
  from documents uploaded through the dashboard's new **Runbooks** tab
  (`rag/local_store.py`: paragraph chunking + JSON-file-backed store).
  Rarity-weighted (TF-IDF-style) keyword scoring, stopword filtering, and
  Kubernetes pod-hash-suffix stripping from the query — no embeddings, no
  vector DB, no external LLM call.
- **Unchanged**: `HttpRunbookRetriever` against the external doc-intelligence
  service stays exactly as originally planned — still 🔲 (unbuilt), for
  whenever network access to that service is available. The factory
  (`get_runbook_retriever`) now checks the local store first, falls back to
  the (still unbuilt) HTTP branch, then to `NullRunbookRetriever`.
- **New**: `rag/query_log.py` — records every runbook-retrieval attempt
  (not LLM calls; this project has no LLM call anywhere in the default
  extractive pipeline), hit or miss, so a pattern of zero-hit queries
  becomes the signal for "write a runbook for this."
- **New FastAPI endpoints**: `POST/GET /runbooks`, `DELETE /runbooks/{name}`,
  `GET/DELETE /runbook-queries`.
- **New Streamlit tabs**: **📝 Runbooks** (upload/list/delete, metrics) and
  **📊 Query Log** (stats, filter, CSV export, clear-with-confirmation) —
  styled after the sibling ChatBOT project's admin console
  (`/home/milind/ChatBOT/embeddingGUI.py`).
- **27 new tests** added (`tests/test_runbook_rag.py`); full suite at
  92/92 passing, ruff clean.

**Real bug caught by live testing (not by pytest) and fixed**: the
retriever was originally resolved once in `ExtractivePipeline.__init__` and
cached — so a runbook uploaded through the dashboard *after* the backend
started never actually took effect until a redeploy. Found via Streamlit's
`AppTest` harness against a real running backend: uploaded a doc, fired a
webhook alert, saw `suggested_next_steps` still show the neutral "no
runbook source" note instead of the upload. Fixed by resolving the
retriever fresh inside `ExtractivePipeline.run()` on every incident
instead — re-verified live, now matches immediately after upload with no
redeploy needed.

Also fixed in passing: a stale Dockerfile comment left over from before the
0.3.8 Unix-domain-socket redesign (claimed FastAPI ran on `127.0.0.1:8081`;
it actually runs behind `/tmp/rca-agent.sock`, no TCP port at all).
