## WHAT WAS BUILT

### 1. Full project scaffold (`src/rca_agent/`)
- `config.py` — pydantic-settings, env prefix `RCA_`. Key settings:
  `cluster_enabled`, `kubeconfig_mode` (auto/incluster/local), `namespace`,
  `nf_selector` (empty = whole namespace), `reasoning_mode` (extractive default),
  `graph_rebuild_interval_seconds` (60), `runbook_rag_url`, host/port.
- `models/` — `Alert`/`AlertmanagerPayload`/`KubeEvent` (inputs);
  `IncidentReport`/`Hypothesis`/`Evidence`/`Citation`/`Severity` (output).
- `graph/dependency_graph.py` — NetworkX MultiDiGraph, timestamped upserts +
  change log. `NodeKind`, `EdgeKind` (calls/runs_on/mounts/managed_by/selects),
  `Health` enum (healthy/degraded/down/unknown). `roll_up_health()`,
  `managed_pods()`, `upstream()/downstream()`, `neighborhood()`, `build_demo_graph()`.
- `graph/builder.py` — `GraphBuilder._rebuild_from_cluster()`: discovers
  nodes/workloads/replicasets/pods/configmaps/secrets/pvcs/services; builds
  runs_on/managed_by/mounts/selects edges; pod health from phase+container
  statuses (OOMKilled/CrashLoopBackOff/readiness); rolls up to workload.
  **Permission-tolerant** via `_safe_list()` (403/forbidden on a resource type is
  skipped with a warning, not fatal).
- `tools/kube_client.py` — read-only client bootstrap, auto/incluster/local
  config detection. kubernetes pkg imported lazily (in `[cluster]` extra).
- `tools/query_tools.py` — `StubQueryTools` (demo evidence). `get_query_tools`
  FALLS BACK to stub even when cluster_enabled (KubeQueryTools NOT yet built).
- `reasoning/` — extractive pipeline (triage→gather→graph_walk→change_correlation
  →hypothesize_rank→report) + LangGraph flow wrapper (falls back to extractive).
- `rag/runbook_retriever.py` — `StubRunbookRetriever` (keyword) + HTTP stub.
- `webhook/app.py` — FastAPI. Endpoints: `/healthz`, `/readyz`, `/graph/stats`,
  `/graph/neighborhood/{node}`, `/graph/view` (+ `?hide_orphans`),
  `/graph/view/{node}?radius=`, `/webhook/alertmanager`, `/docs`.
  Startup build is RESILIENT (`_safe_rebuild`): cluster/kubeconfig failure logs
  and serves empty graph; background `_refresh_loop` rebuilds every 60s (threaded,
  atomic swap).
- `graph/visualize.py` — pyvis → interactive HTML. Nodes colored by health,
  shaped by kind; edges labeled by relationship. **Physics freezes after layout**
  (stops drifting); **orphan (edgeless) nodes hidden by default** on full view.

### Run sequence (reproduced & working)
```bash
# 1. laptop -> copy image to jumpserver
scp /home/milind/rca-agent-0.1.0.tar.gz eagamil@10.242.70.7:~/

# 2. jumpserver: oc login (writes token kubeconfig to ~/.kube/config)
oc login https://api.cobra-2a-openshift.bete.ericy.com:6443 -u eagamil -p <REDACTED-PASSWORD> --insecure-skip-tls-verify

# 3. jumpserver: load + run (SINGLE LINE to avoid paste corruption)
docker rm -f rca-agent
docker load -i ~/rca-agent-0.1.0.tar.gz
docker run -d --name rca-agent --network host --user 1744:1744 -e RCA_CLUSTER_ENABLED=true -e RCA_KUBECONFIG_MODE=local -e RCA_NAMESPACE=plantx2avzwcspgc-y-oc-consp-301 -e KUBECONFIG=/kube/config -e RCA_PORT=8004 -e HOME=/tmp -v ~/.kube/config:/kube/config:ro rca-agent:0.1.0
docker logs -f rca-agent

# 4. laptop: tunnel + view
ssh -L 8004:localhost:8004 eagamil@10.242.70.7
#   http://localhost:8004/graph/view        (full, frozen, orphans hidden)
#   http://localhost:8004/graph/view/<pod>?radius=2
#   http://localhost:8004/graph/stats
```

### Key gotchas solved this session
- `--network host` needed so the API server URL resolves from inside container.
- kubeconfig is mode 600 (eagamil-only) → run container as `--user 1744:1744`
  + `-e HOME=/tmp` so uid 1744 can read the mounted config. (NOT chmod 644.)
- Multi-line `docker run` got corrupted on paste → use SINGLE-LINE command.
- `InsecureRequestWarning` in logs = harmless (TLS verify off from oc login).
- Startup no longer crashes on kube errors (serves empty graph, retries).

## REAL CLUSTER FINDINGS (cSAEGW-C / Ericsson PCC)

Namespace = ONE Helm umbrella release (`eric-cloud-native-base` chart 368.1.2,
"PCC 1.42 CP0 rev PA28"). 1485 nodes total. Label hierarchy on pods:
- `app.kubernetes.io/instance` / `release` = whole release (≈ namespace)
- **`app.kubernetes.io/name` = individual component** ← use THIS to group/list
- `statefulset.kubernetes.io/pod-name` = individual pod
- `applicationId` (= `plantx2avzwcpcsm-y-oc-conss-002`, note: value mismatches
  the namespace — templating artifact) = WHOLE-deployment identity, in
  metrics/licensing config, NOT a reliable per-pod label. Use only as graph-level
  metadata, not for component grouping.

Components present (from Helm values, enabled):
- **eric-pc-sm** (the SMF/PGW/SGW NF logic): controller, diameter, http-client,
  ip-allocator, notification-forwarder, nsmf-forwarder, sgw-session,
  smf-pgw-session, udp-forwarder, geo-red-forwarder, target-database-master-rd,
  target-database-replica-rd, br-agent.
- Routing/data-plane: eric-pc-routing-engine(-api), eric-pc-routing-aggregator,
  eric-pc-vpn-gateway-forwarder, eric-pc-up-timer-wheel, eric-pc-kvdb-rd-server/operator.
- Platform (eric-cloud-native-base): eric-cm-mediator, eric-ctrl-bro,
  eric-data-* (zk, message-bus-kf, search-engine, object-storage-mn),
