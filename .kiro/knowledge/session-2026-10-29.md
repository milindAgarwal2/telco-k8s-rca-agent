## GIT / PUSH MECHANISM (important — this cost a lot of tokens to solve once)
Remote `origin` = GitLab `gitlab.rosetta.ericssondevops.com/milind.agarwal/
telco-k8s-rca-agent.git`, behind **Cloudflare Access (Zero-Trust SSO)**. A plain
`git push` gets 302-redirected to a cloudflareaccess.com login and fails
(`unable to update url base from redirection`). TWO auth layers needed at once:
1. **CF Access** — JWT from `cloudflared access token --app <repo-url>`, sent as
   a **`CF_Authorization` cookie via `http.cookieFile`** (NOT a header — header
   form was tried and fails).
2. **GitLab** — PAT basic-auth (currently embedded in the origin URL).
`scripts/git-push.sh` does exactly this (mirrors the proven mop-tool helper):
writes the JWT to a temp Netscape cookie jar, runs `git -c http.cookieFile=... <push|fetch>`.
If the CF token expired (~24h): `cloudflared access login <repo-url>` once, re-run.
NOTE: the PAT is in plaintext in the origin URL (hygiene: move to ~/.git-credentials
later; not urgent). `cloudflared` IS installed on this host (/usr/local/bin).
