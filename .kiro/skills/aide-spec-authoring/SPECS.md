# Specification authoring skill specification

## Intent

Convert a request into reviewable, testable Kiro requirements using repository
evidence and EARS acceptance criteria.

## Contract

Requirements have stable identifiers, observable outcomes, explicit scope and
exclusions, traceable evidence, and clearly labeled assumptions. Output follows
the repository's existing specification layout and remains draft until review.

## Interactions and failures

The skill reads the primary knowledge base, secondary OpenWiki, folder
specifications, source, schemas, and tests. Conflicts and insufficient evidence
are recorded as review questions rather than invented details.
