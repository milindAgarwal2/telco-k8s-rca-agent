# Architecture and contracts skill specification

## Intent

Create targeted, evidence-backed HLD, LLD, diagrams, and interface contracts
that connect requirements to implementation and verification.

## Contract

Current, proposed, inferred, and unknown states remain distinct. Changed
contracts name producers, consumers, invariants, errors, compatibility, and
verification evidence. Diagrams supplement rather than replace written meaning.

## Failure handling

Unverifiable architecture is labeled unresolved. Conflicting evidence is
presented for review without fabricating a resolution.
