# Repository structure and navigation

## Layout decision

This is a `src/`-layout Python package. All runtime code lives under
`src/rca_agent/`; everything outside it is build, deploy, docs, tests, tooling,
or non-shipping planning artifacts. When reasoning about product behavior,
start in `src/rca_agent/` and treat the root-level `PLAN*.md`, `NOTES-*.md`,
`*.pptx`, `*.docx`, and `*.xlsx` files as background notes, not the service.

## Runtime package: `src/rca_agent/`

One FastAPI process wires these cohesive sub-packages together. Dependency
direction flows from `webhook` inward to `reasoning`, `graph`, `detection`,
`tools`, `rag`, `impact`, and `models`; `config.py` is a leaf consumed widely.

| Path | Owns | Notes |
| --- | --- | --- |
| `webhook/app.py` | FastAPI app, endpoints, lifespan, background loops, shared singletons | composition root |
| `webhook/ui.py`, `webhook/templates/`, `webhook/static/` | Server-rendered dashboard (Jinja2 + Bootstrap + HTMX) | static assets vendored, offline-safe |
| `webhook/pptx_report.py` | Per-incident RCA PPTX export | lazy `python-pptx` |
| `config.py` | Env-driven settings (`RCA_` prefix), cached singleton | pydantic-settings |
| `graph/` | NetworkX dependency graph: build/refresh, traversal, health rollup, anchors, pyvis visualize | in-memory state |
| `detection/event_watcher.py` | Event + status polling, dedup, correlation, incident pool | in-memory incidents |
| `tools/` | Read-only kube query tools (`query_tools.py`) + kube client loader (`kube_client.py`) | stub vs. real via factory |
| `reasoning/` | `flow.py` entry → `extractive.py` six steps (`steps.py`, `state.py`) → optional `llm_rerank.py` / `runbook_synth.py` | rules first, LLM second |
| `rag/` | Runbook retriever interface + factory, local store, opt-in semantic store, query log | priority: semantic → TF-IDF → HTTP (TODO) → null |
| `impact/` | Service-area mapping from an `.xlsx` workbook | lazy `openpyxl` |
| `models/` | Input (`alert.py`) and output (`incident.py`) pydantic schemas | contracts |
| `eval/` | Offline fault-injection accuracy harness (`python -m rca_agent.eval`) | uses fake cluster |

## Entrypoints

- **Runtime:** `rca-agent` console script → `rca_agent.webhook.app:main`
  (`pyproject.toml [project.scripts]`); or `uvicorn rca_agent.webhook.app:app`.
- **Build/packaging:** `pyproject.toml` (setuptools, `src/` discovery, package
  data for dashboard templates/static).
- **Dev loops:** `Makefile` targets — `make check` (lint + test), `make test`,
  `make lint`, `make fmt`, `make eval`, `make install`. The Makefile uses
  `.venv/bin/python`; `python` is not assumed on PATH.
- **Deployment:** `deploy/helm/` (chart, `values.yaml`, `templates/`) and the
  root `Dockerfile`; `docker/` holds the single-process `entrypoint.sh`,
  sidecar Dockerfile, and deploy scripts.
- **Tests:** `tests/` (pytest; `pythonpath = ["src"]`, `testpaths = ["tests"]`).

## Where contracts, config, and generated artifacts live

- **Schemas / contracts:** `src/rca_agent/models/` (API I/O) and the HTTP
  endpoints in `webhook/app.py`.
- **Configuration:** `src/rca_agent/config.py` (all `RCA_*` env vars); the Helm
  chart maps a subset to container env in `deploy/helm/templates/deployment.yaml`.
- **Curated docs:** `knowledge-base/` (reviewed HLD/LLD/SPECS — primary) and
  per-folder `SPECS.md` files; `openwiki/` and `docs/arch/*.mmd` as secondary
  navigation. `docs/` also holds rendered architecture diagrams.
- **Generated / do-not-hand-edit:** `openwiki/` pages are regenerated by the
  scheduled GitHub Actions workflow — update source/docs and let OpenWiki
  regenerate (see `AGENTS.md`). `.aide/` holds AIDE baseline/workflow state;
  `.kiro/` holds steering and skills. Avoid editing egg-info, `.pytest_cache`,
  and `.ruff_cache`.

## Navigating a change to producers, consumers, and verification

- A new or changed **HTTP behavior** → `webhook/app.py` (+ `ui.py` for UI),
  schemas in `models/`, verified by `tests/test_webhook.py`,
  `tests/test_query_tools.py`.
- **Reasoning / ranking** → `reasoning/steps.py` and `extractive.py`, verified
  by `tests/test_reasoning.py`, `test_pipeline_cluster.py`,
  `test_llm_rerank.py`.
- **Graph model** → `graph/`, verified by `tests/test_cluster_graph.py`.
- **Detection** → `detection/event_watcher.py`, verified by
  `tests/test_event_watcher.py`, `test_anchor_phase*.py`.
- **Runbook RAG** → `rag/`, verified by `tests/test_runbook_rag.py`,
  `test_semantic_rag.py`, `test_runbook_synth.py`.
- **Service-area impact** → `impact/`, verified by `tests/test_impact_*.py`.

## Naming and placement conventions (from current evidence)

- Each sub-package carries a reviewed `SPECS.md` describing its responsibility;
  read it before changing that package.
- Factories isolate variant/failure behavior: `tools/query_tools.py::get_query_tools`,
  `rag/runbook_retriever.py::get_runbook_retriever`. Optional dependencies are
  imported lazily so absent extras degrade rather than crash.
- Config keys are snake_case fields surfaced as `RCA_`-prefixed env vars.
